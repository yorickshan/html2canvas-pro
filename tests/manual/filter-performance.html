03 / Performance · Draft PR #239

Measure the cost of correctness

Reproducible timings for the real SVG surface helper and full DOM captures. Run locally in this browser or inspect a saved CLI report. No requests or telemetry are sent by the benchmark.

No universal “fast enough” claim.

Hardware, browser and image entropy matter. A faster release capture can be missing blur or applying opacity incorrectly. A memory-budget fallback is explicitly labeled, not counted as a successful filtered rendering.

What is measured?

Surface: 512², 1000² and 2000² raster pixels, flat and seeded noisy images, blur and blur + shadow. Compare an opacity-only copy, the production SVG pipeline and a benchmark-only Canvas filter alternative. Native filtering uses two passes so opacity is applied after filtering, not before shadow merge.

Full capture: published 2.4.3 and the current draft on identical DOM: no-effects controls, combined effects, 50 sparse layers, 12 nested filters and a 2600² over-budget case. Surface source creation is outside its timer; DOM cloning/rendering is inside full-capture timing.

Each case records its first observation separately, excludes two warmups, then rotates backend order. Total time includes a full pixel readback to flush deferred drawing. Encode, decode, submission and readback durations remain available in JSON. With nine samples, nearest-rank p95 equals the maximum; it is not a stable tail-latency estimate.

Center opacity, outside blur, actual SVG usage and clone cleanup are checked. These are sanity checks, not full visual equivalence. The existing pixel-regression and allocation suites remain necessary. This page does not measure peak browser-process or SVG-decoder memory.
